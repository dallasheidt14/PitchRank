# MatchBalance tournament intake review — September 11, 2026

This is the historical review of commit `4c14a49b1`, before the completed-event intake changes in `69b419d9c`. Intake findings were addressed in that implementation; comparison and reseeding work remains deferred. See the [current Backtest workflow and validation](../../docs/matchbalance-backtest-intake.md) for the implemented behavior. Source line references below describe the reviewed baseline.

The intake is a useful foundation for collecting a completed tournament. It is not yet a verified reconstruction that can support a defensible claim that MatchBalance would have seeded that same event better. Several missing connections are explicitly deferred in the existing design; the defects below also affect code that is already implemented.

The intended product should preserve the event the director actually ran, link its entrants to PitchRank, freeze the information available before seeding, and compare the original and proposed placements under the same format and prediction method. Actual results should validate the forecasts. Outcomes of hypothetical games must remain labeled as estimates.

**What is already useful**

- The new intake reads actual standings tables for pool membership and preserves provider registration IDs. It distinguishes pool, cross-pool, and labeled bracket fixtures rather than guessing all membership from who played whom.
- The new matching path is designed to read PitchRank without creating teams, aliases, or scrape requests. Registration-keyed links persist across sessions and resolve merged team IDs.
- Paid-walk recovery, partial-overwrite protection, visible unreadable-division warnings, and atomic JSON file replacement provide a substantial base.
- An optimizer, basic schedule simulator, run provenance, movement recommendations, and report renderer already exist downstream.

**Findings, ordered around the intake-to-evidence workflow**

1. **High — an interrupted walk can associate the new structure with the previous event.** `_park_event_roster` updates the probe and divisions before updating the result's event ID. The save action reads these separate fields without verifying they belong to one generation. An offline interruption reproduction produced save inputs containing `OLD-EVENT` with `NEW-GROUP` and `is_complete=True`. Link synchronization has a generation check; structure saving needs equivalent protection. Park one immutable event snapshot, or require a shared generation identifier before display and save. [State writes](C:/PitchRank/tournament_intake.py:3801), [later event-ID write](C:/PitchRank/tournament_intake.py:4530), [save boundary](C:/PitchRank/src/tournaments/backtest_event_intake.py:281).

2. **High — historical event age and current lookup age are mixed together.** A literal `U12 Boys` remains `u12`, whereas `B2014` becomes today's `u13`. Those ages flow directly into current GotSport and PitchRank lookups. A saved real division page contains the historical header `Male U12` and the label `B2014 Silver 2 (9v9)`, illustrating why these are separate concepts. The fallback can miss the real team or accept a younger same-name squad. Direct provider-ID matching avoids this particular age-filter problem. Store event date/season, the published age, and the current identity-search cohort separately; do not infer a historical team's identity from today's age label alone. [Parser](C:/PitchRank/src/tournaments/gotsport_event_roster.py:223), [wall-clock conversion](C:/PitchRank/src/tournaments/gotsport_event_roster.py:317), [lookup filter](C:/PitchRank/src/tournaments/roster_resolver.py:427).

3. **High — some published results are lost, and a completed walk is not necessarily replay-ready.** The score parser accepts only a bare score such as `3 - 3`. A real semifinal result, `3 - 3 PKS: 4 - 3`, becomes two missing scores and no warning. Four saved corpus fixtures exhibit this defect. Preserve raw result text, regulation scores, shootout scores, match status, and advancing team separately. Also distinguish discovery completion, structural completeness, and replay readiness: the existing `is_complete` deliberately describes the roster walk rather than the fixture data. [Score parser](C:/PitchRank/src/tournaments/gotsport_event_structure.py:232), [real shootout source](C:/PitchRank/tests/fixtures/gotsport/event_45394__group_469715.html:1374), [saved completeness flag](C:/PitchRank/src/tournaments/backtest_event_intake.py:288).

4. **Medium — successful identity matches cannot be reviewed and corrected on the new surface.** It renders counts and controls for outstanding teams, but no all-team mapping table. Already matched or manually overridden teams leave the editable list; saved overrides are restored before filtering. An incorrect saved link therefore has no correction control on this surface. Provide every entrant's original identity, chosen PitchRank team, match method, and edit/remove controls. [Outstanding-only filter](C:/PitchRank/tournament_intake.py:4644), [render path](C:/PitchRank/src/tournaments/backtest_event_intake.py:258).

5. **Coverage gap — the structure is not a manifest of every discovered division.** The shared walker filters out divisions outside ranked cohorts, and failed division-page requests produce warnings without an unreadable division record in the returned structure. A saved structure alone cannot account for every discovered group. Preserve a discovery manifest with included, intentionally excluded, and failed divisions. Distinguish full-event capture from the subset eligible for PitchRank analysis. [Requested cohort filter](C:/PitchRank/tournament_intake.py:3722), [division filtering](C:/PitchRank/src/tournaments/gotsport_event_roster.py:824), [failed-page handling](C:/PitchRank/src/tournaments/gotsport_event_roster.py:960).

6. **Planned product gap — played fixtures do not encode the tournament's advancement rules.** The current fixture record has actual participants and a label such as `Final`; it cannot express `winner of semifinal A`, `second in pool B`, wildcards, or the event's scoring and tiebreaker rules. Final standings are explicitly not original seeds. Preserve source slot labels and model progression rules, with documented operator confirmation where the provider does not publish enough evidence. An exact replay must not replace missing rules with generic assumptions. [Fixture model](C:/PitchRank/src/tournaments/gotsport_event_structure.py:184), [standings-position meaning](C:/PitchRank/src/tournaments/gotsport_event_structure.py:49).

7. **Planned integration gap — the new exact intake does not feed Run backtest.** The application explicitly says that the triage list, division editor, and run button still consume the legacy intake. That older scrape can write aliases and review rows. Downstream, the request contains pool sizes rather than the captured fixture graph, and the simulator infers playoffs from total game counts while always generating full pool round robins. One saved six-team format actually has two pools playing nine cross-pool games and a final; the old inference can produce six within-pool games and four playoffs instead. Equal totals do not establish the same tournament. Connect the new event snapshot directly and reject unsupported rules before running. [Current UI boundary](C:/PitchRank/tournament_intake.py:4750), [run payload](C:/PitchRank/src/tournaments/run_orchestrator.py:521), [format inference](C:/PitchRank/scripts/backtest_tournament_cohort.py:1060), [existing scope decision](C:/PitchRank/.turbo/specs/matchbalance-exact-event-structure.md:23).

8. **High — historical reseeding can use information from after the tournament.** Entrants and seed strengths are always initialized from current `rankings_full`. Missing per-team historical snapshots can be synthesized from those current inputs and stamped with the requested old date. The point-in-time path reports this as a warning and continues. Current scores also influence initial placement and standings tiebreaks. Separately, recent-history fetching starts relative to today, which can omit the legitimate history needed for older events; model loading does not establish training-cutoff eligibility here. Require frozen inputs before the event's seeding deadline, validate model eligibility, and mark missing historical evidence as ineligible for a historical proof claim. [Live ratings](C:/PitchRank/scripts/backtest_tournament_cohort.py:878), [synthetic fallback](C:/PitchRank/scripts/backtest_tournament_cohort.py:431), [warning-only continuation](C:/PitchRank/scripts/backtest_tournament_cohort.py:1015), [history window](C:/PitchRank/scripts/backtest_tournament_cohort.py:184).

9. **High — reversing matchup order can assign the predicted win to the wrong team.** Both predictor caches use an unordered pair key but return predictions whose scores and winner refer to ordered team A/team B. An offline reproduction returned the same `team_a, 3-0` object for both `predict(Alpha, Bravo)` and `predict(Bravo, Alpha)`. Optimization primes these caches before simulation, so a changed order can invert a winner and knockout advancement. Cache ordered predictions or reverse every directional field on retrieval. [Point-in-time cache](C:/PitchRank/scripts/backtest_tournament_cohort.py:654), [Python cache](C:/PitchRank/scripts/backtest_tournament_cohort.py:568).

10. **High — the current improvement comparison does not isolate the benefit of reseeding.** It compares actual observed margins with one optimized replay built from rounded predicted scores. Rounded expectations suppress outcome variation, so fewer predicted blowouts can occur even without a better draw. There is no equivalent simulation of the director's original placements. Compare original versus reseeded placements using identical frozen inputs and simulation methods; use expected rates or repeated probabilistic simulations with uncertainty. Keep actual results as a separate forecast-validation baseline. Report estimated benefits rather than saying the hypothetical draw already reduced mismatches. [Comparison](C:/PitchRank/scripts/backtest_tournament_cohort.py:1077), [rounded-score metrics](C:/PitchRank/src/tournaments/schedule_simulator.py:291), [report wording](C:/PitchRank/src/tournaments/reports/compute.py:104).

11. **Medium — the legacy actual-results query can mix event editions.** Without an explicit override, it fetches by event name and division name without event-ID or date boundaries, and requests at most 1,001 rows. Annual events can reuse both names. The captured event edition's fixtures should own the baseline, with explicit reconciliation against provider match IDs and dates. [Baseline query](C:/PitchRank/scripts/backtest_tournament_cohort.py:927).

**Recommended next milestone**

Finish one verified event intake before expanding reseeding:

1. Fix event-generation consistency, historical cohort identity, and result parsing. Make every team link inspectable and correctable.
2. Use one completed GotSport event as the acceptance case. Account for every discovered division; reconcile team membership and fixtures; preserve result statuses, source evidence, event dates, and advancement rules. Explicitly identify unknowns and analysis exclusions.
3. Save and reload the same verified event snapshot. Treat a complete scrape, a saved snapshot, and a replay-ready division as distinct states. Allow analysis only for verified divisions.
4. Connect that snapshot to the runner. First reproduce the original event with recorded results, proving the format and progression agree before changing any team placement.
5. Freeze legitimate pre-event ratings, history, and model version. Fix prediction orientation. Apply the same capacities, match opportunities, progression rules, and confirmed director constraints to original and reseeded placements.
6. Compare both draws under the same model, show uncertainty, and validate forecasts across multiple held-out events. Director output should show original versus recommended assignments, expected close games and blowout risk, team moves, coverage, and the reasons for each recommendation.

The first acceptance deliverable should be a verified tournament reconstruction with a clear readiness result. The sales comparison follows that contract.
