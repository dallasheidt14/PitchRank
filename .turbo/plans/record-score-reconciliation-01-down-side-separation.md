# Plan: Down-side record separation (Stage 1)

## Context

The published board over-rewards strength-of-schedule: mediocre-record teams on brutal schedules sit too high (prod scores 7/23 against the owner's 23-team ground truth). The prior one-sided SOS-credit cap reached 14/23 but demoted genuine elites because a single global cap strength couldn't distinguish a 47%-win inflated team from a 63%/90%-win elite — its `record_score` was **cohort-relative** (a within-cohort z-score), which compresses strong records in elite cohorts. This shell builds the **down-side** of a two-sided record↔score reconciliation: an **absolute-anchored** `record_expected` score (so strong records are near-uncappable in any cohort) and a self-normalizing down-pull that lowers only SOS-inflated teams toward their record-expected level — never raising any score and never touching `mu`/SOS/SCF/ML. It is the most important credibility win and ships independently once it clears the R10a fixture gate (on the full-pipeline `rank_in_cohort_final` board) and the published-score backtest.

**Locked design hypothesis (the shape, not the numbers):** `record_expected` is an **absolute-anchored** index of a **windowed, draw-aware** record — all of the team's games within the rankings lookback window (`WINDOW_DAYS`), **not** the selected ≤30-game subset, draws counted (points-based) — with `win_component` using **absolute thresholds, not within-cohort z-scoring**. Before any down-pull, `record_expected` is **explicitly converted** to a `powerscore_core`-comparable value `record_expected_core` via a per-cohort **affine crosswalk** `cohort_core_center + β·(record_expected − R0)` that preserves the absolute top-anchoring; the down-pull tolerance is **cohort self-normalized** from the dispersion of `powerscore_core − record_expected_core`; the effect is **one-sided, continuous, and games-ramped**. The sweep may tune the breakpoints, weights, `β`, `R0`, and the tolerance multiplier **only within this shape** — it may **not** revert to a cohort-relative (z-score) record anchor, **nor** compare the absolute anchor to `powerscore_core` without the crosswalk, without reopening the design (the cohort-relative compression demoted SOLAR/ALBION; see `.turbo/sos-credit-cap-scorecard.md`).

Generalize `apply_sos_credit_cap` into a sibling transform on the same `(team_df, cfg)` contract, same hook position (a second guarded block right after 1831), same `power_presos`/snapshot convention, same env-backed config dials, same `_cfg_dict`/staging-harness/ground-truth/backtest plumbing. The absolute `record_expected` is then explicitly converted to a `powerscore_core`-comparable `record_expected_core` via a per-cohort affine crosswalk (preserving top-anchoring) before any comparison. ## Implementation Steps

1. **Add the absolute-anchored `record_expected` index** (`src/etl/glicko_engine.py`)
   - **Windowed, draw-aware record basis.** Compute each team's record from **all** its games within the rankings lookback window (`WINDOW_DAYS` via the existing `select_games`/window logic) — **NOT** the ≤30-game `select_games_balanced` subset that `team_df.wins/games_played` are summarized from (that subset is outcome-biased for >30-game teams). Count draws as first-class — a points-based rate `(W + 0.5·D)/games` (or 3-1-0 normalized), not `wins/games_played`. This requires a per-team windowed-record derivation from `games_df` (the cohort game set), not the selected-window aggregates on `team_df`.
   - Add a helper that computes `record_expected = cfg.RECORD_RECONCILE_WIN_WEIGHT * win_component + cfg.RECORD_RECONCILE_GD_WEIGHT * gd_component` per team:
     - `win_component`: an **absolute** monotone map of the windowed draw-aware win/points rate to [0,1] via fixed config breakpoints (e.g. a logistic/piecewise map anchored so ~0→~0, ~0.5→~0.5, ≥~0.85→~0.95) — explicitly **not** `sigmoid_zscore_normalize` (858-875), which is cohort-relative.
     - `gd_component`: a bounded absolute map of windowed per-game goal differential, clamped to a configured band, mapped to [0,1].
   - **Constrain `record_expected` to [0,1]**: weights sum to 1 (convex blend of two [0,1] components) **and** clip to [0,1].
   - **Scale crosswalk → `record_expected_core` (REQUIRED before any down-pull math).** Convert the absolute `record_expected` into a `powerscore_core`-comparable value via the per-cohort affine projection `record_expected_core = cohort_core_center + cfg.RECORD_RECONCILE_BETA * (record_expected − cfg.RECORD_RECONCILE_R0)`, where `cohort_core_center` is the cohort's `powerscore_core` center (median/mean) and `R0` is a fixed absolute baseline. This absorbs the per-cohort offset (so a cohort with systematically high/low records isn't pulled wholesale) while the absolute `(record_expected − R0)` term preserves top-anchoring (a strong record → high `record_expected_core` in any cohort). `β`/`R0` are sweep-tuned within this shape. **All down-pull math below operates on `record_expected_core`, never the raw absolute anchor.**

2. **Frozen pre-reconciliation snapshot + single-pass scaffold** (`src/etl/glicko_engine.py`)
   - Inside the new transform, compute all cohort statistics once from the **input** `powerscore_core` column **before the single masked write** — mirror `apply_sos_credit_cap`'s `df = team_df.copy()` pre-mutation read; no separately materialized snapshot is needed: per-team `record_expected`, its `record_expected_core` conversion, and the cohort dispersion of `(powerscore_core − record_expected_core)`.
   - **Pin the dispersion estimator** (recommended default: population std, `ddof=0`; MAD as a robust alternative), with a **nonzero tolerance floor** for zero-variance / homogeneous cohorts (so the continuous pull never collapses to a hard cap / rank cliff) and a **minimum-cohort-size guard** (small cohorts fall back to the floor). The exact estimator / floor / min-size are sweep-tuned within this shape. Apply the down-pull in a single pass with no within-run recomputation (idempotent).

3. **Down-pull reconciliation stage** (`src/etl/glicko_engine.py`, generalizing `apply_sos_credit_cap` at 1372-1426)
   - Add `apply_record_score_reconciliation(team_df, cfg)` mirroring `apply_sos_credit_cap`'s structure/contract; call it from a new guarded block immediately after the existing cap block at 1829-1831 (after the `powerscore_core` if/else converges, before `powerscore_adj`).
   - `tolerance = cfg.RECORD_RECONCILE_DOWNPULL_K * dispersion(powerscore_core − record_expected_core)` (cohort-self-normalized). Where `powerscore_core > record_expected_core + tolerance`, reduce it toward `record_expected_core + tolerance` — one-sided (`clip(upper=...)`/`minimum`), continuous, games-ramped via the `games_ramp` device (1421-1422). Strong records (high `record_expected_core`) keep full credit; never raises a score.
   - Set `power_presos` to the pre-reconciliation `powerscore_core` inside the function (the `:1918-1921` guard preserves it). Guard the whole block with `if cfg.RECORD_RECONCILE_ENABLED:` (default off). Leave the committed `apply_sos_credit_cap` in place (default-off, superseded prior art); do not delete it in this shell.
   - **Mutual exclusion (fail-closed):** the old cap and the new reconciliation must never stack. `GlickoConfig` shall **raise** if both `SOS_CREDIT_CAP_ENABLED` and `RECORD_RECONCILE_ENABLED` resolve on (a `__post_init__` check), so no run — staging or prod — can produce a doubly-shaped board that masquerades as a clean Stage 1 test.

4. **Config dials + cache fingerprint + staging plumbing**
   - `src/etl/glicko_config.py:154-166` — add env-backed default-off dials mirroring the `SOS_CREDIT_*` block: `RECORD_RECONCILE_ENABLED` (bool, default off), `RECORD_RECONCILE_WIN_WEIGHT`, `RECORD_RECONCILE_GD_WEIGHT`, `RECORD_RECONCILE_DOWNPULL_K`, `RECORD_RECONCILE_BETA`, `RECORD_RECONCILE_R0` (the affine crosswalk slope + baseline), `RECORD_RECONCILE_GD_CLAMP`, the absolute win% breakpoint constants, and `RECORD_RECONCILE_MIN_GAMES_FULL` (games-ramp). Provisional defaults; sweep-tuned within the locked shape.
   - `src/rankings/calculator.py:2145-2146` — extend `_cfg_dict` with the new flag + the output-affecting constants (short-key `getattr(...,None)` style) so each variant gets a distinct cache hash.
   - `scripts/run_scf_off_staging.py` — add `--record-reconcile {on,off}` + `--record-downpull-k` (and the other dials) mirroring `--sos-credit-cap`/`--sos-credit-max`: argparse (395-406), `_force_scf_env` os.environ force (114-125), `_assert_effective_config` print+assert (128-156), and thread through `_run_build` (330). Keep defaults backward-compatible. `_assert_effective_config` shall also **abort if both the cap and reconcile flags resolve on** (belt-and-suspenders for the `GlickoConfig` guard, since the harness forces flags via env).
   - Mirror a config unit test (the `SOS_CREDIT_*` env-parse test pattern) for the new flag/floats.

   - Add a `VARIANTS` entry (`backtest.py:57-78`), e.g. `"record_reconcile_down": ({"RECORD_RECONCILE_ENABLED": True, ...}, {})`; the gate is `ord_acc_ps_adj`/`ord_acc_ps_core` (220-221) not materially worse vs `baseline_prod` (engine-level prediction guardrail).
