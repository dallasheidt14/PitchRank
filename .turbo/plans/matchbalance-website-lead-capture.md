# Plan: MatchBalance Website Lead Capture

## Context

MatchBalance is a per-cohort seeding cheat sheet for tournament directors that today exists
only as an operator tool (`tournament_intake.py`, Seeding tab). Directors cannot discover it,
see the deliverable, learn the price, or ask for it. The approved spec
(`.turbo/specs/matchbalance-website-lead-capture.md`) adds the front door only: a public
sales page at `/matchbalance` with pricing tiers and a real sample, a spam-protected inquiry
form whose submissions are saved to a server-only `matchbalance_leads` table and announced
by email, and an admin Leads page under `/mission-control`. The operator workflow stays in
Streamlit; no payments, accounts or Streamlit changes.

Every piece has a working model in the repo. The plan is assembly, with three deliberate
deviations from the nearest prior art (see Proposed Alignment): the lead insert is awaited
through the service client so a failed save returns 500; the two emails are awaited (the
feedback route already awaits its send, and an unawaited send on Vercel can be cut off when
the response returns); and the sample asset needs a live ratings read plus the Node
predictor, because the saved run carries only roster and match data.

### Proposed Alignment

Follow the existing patterns everywhere, with three deliberate deviations: **(a)** the lead insert follows `track-team-view/route.ts:39-45` (awaited service client, `error` → 500) rather than the team-card fire-and-forget; **(b)** both email sends are awaited, as `feedback/route.ts:152` already does, rather than fired and forgotten; **(c)** the sample asset reproduces the operator's tiered sheet through the full `render_seeding_pack` chain (live ratings read + Node predictor + Playwright PDF), with the page-one PNG rasterised from that PDF by PyMuPDF (`import fitz`, installed in this environment) in a one-off script that is not committed. The route's guard order is the feedback route's (rate limit last), not the spec's original numbering; the spec has been updated to match. Everything else — page shape, form state machine, honeypot, sender contract, migration access pattern and guard test, admin page and `errors[]` data function, footer link, FAQ and breadcrumb schema — has a direct model to mirror. `BlogFAQSchema` is reused as-is; no new schema component.
