### Convention Anchors
- RPC migrations: created via `supabase migration new <name>`; `LANGUAGE sql STABLE` (read-only, no `SECURITY DEFINER`); end with `GRANT EXECUTE ... TO anon, authenticated`. State rank = `ROW_NUMBER()` per cohort post-filter on `status='Active'`; no persisted arbitrary-cohort state-rank column.
- `rankings_full` joins: `JOIN teams t ON t.team_id_master = rf.team_id`; names/state come from `teams`, never `rankings_full`. Anon role has a 3s statement timeout — edge-route RPCs must stay under it.
- Tests: pytest in `tests/unit/`; `tests/unit/test_marketing_pipeline.py` (411 lines on `origin/main`) already covers `_to_postiz_payload`, `_resolve_tag_targets`, `enrich_post_with_handles`, `generate_trend_posts` — step 7's `_resolve_tag_targets` changes break 7 of its tests, which must be updated (see step 8). The new social-post tests go in a separate net-new file.
- MT timezone: `MT_OFFSET = timezone(timedelta(hours=-6))` (`:49`); `scheduled_at` is tz-aware MT, converted at draft time.

### Proposed Alignment
Reuse the existing state route, `get_state_rankings`, tagging post-pass, and rotation idiom. Net-new: `get_big_weekend_games` RPC, `/api/infographic/big-games`, `/api/infographic/rankings-live`, rewritten `generate_social_posts()` + helpers, retired old templates.

2. **Migration: `get_big_weekend_games`**
   - `supabase migration new create_get_big_weekend_games` (run via CLI so the filename is generated, never invented).
   - Signature: `get_big_weekend_games(p_start_date DATE, p_end_date DATE, p_rank_ceiling INT DEFAULT 25, p_limit INT DEFAULT 5)`, `LANGUAGE sql STABLE`.
   - Shape (3s-anon-budget aware — **do NOT rank whole cohorts**; a review-time `EXPLAIN ANALYZE` of the rank-the-full-cohort shape measured 1,276 ms warm on the live DB by materializing `ROW_NUMBER()` over ~42K rows across ~367 cohorts; that risks the 3s anon timeout cold):
     1. CTE `candidate_games`: `games` where `is_excluded = false AND home_score IS NULL AND game_date BETWEEN p_start_date AND p_end_date`.
     2. CTE `candidates`: join both sides of `candidate_games` to `rankings_full rf` (`rf.status = 'Active'`) + `teams t ON t.team_id_master = rf.team_id`, keeping per-team `state_code, age_group, gender, power_score_final`. **All three cohort dimensions come from `rankings_full` (`rf.state_code`, `rf.age_group`, `rf.gender`) — never `teams.state_code`** — matching the `WHERE rf.state_code = UPPER(p_state)` idiom of `get_state_rankings` (migration `20260603000000` line 382); the `teams` join supplies only `team_name`/`club_name`. Mixing sources would select a different team set than `get_state_rankings` for the same cohort and break top-25-boundary parity. Require both sides Active and identical `(state_code, age_group, gender)` before any ranking work — plus the other two cohort predicates `get_state_rankings` enforces (migration `20260603000000` lines 391–393): `rf.power_score_final IS NOT NULL` and `t.is_deprecated IS NOT TRUE`. Omitting either lets a NULL-powerscore or deprecated-but-Active team into the rank count that `get_state_rankings`' `ROW_NUMBER()` excludes, shifting every rank below it.
     3. Per-candidate **correlated rank** instead of a window over the cohort: `state_rank = 1 + (SELECT COUNT(*) FROM rankings_full rf2 JOIN teams t2 ON t2.team_id_master = rf2.team_id WHERE rf2.state_code = ... AND rf2.age_group = ... AND rf2.gender = ... AND rf2.status = 'Active' AND rf2.power_score_final IS NOT NULL AND t2.is_deprecated IS NOT TRUE AND (rf2.power_score_final > rf.power_score_final OR (rf2.power_score_final = rf.power_score_final AND rf2.team_id < rf.team_id)))` — the `teams t2` join exists solely for `is_deprecated` (it lives on `teams`); all cohort columns stay pinned to `rankings_full` (see step 2.2), and `rf2.team_id` *is* the `team_id_master`, so it serves as the tiebreaker directly — computed only for teams that survived step 2's same-cohort filter. The composite comparison is the **required tiebreaker**: live data has ~342 tied `power_score_final` groups (max tie size 16), and a bare `>` produces competition-style ranks that disagree with `get_state_rankings`' `ROW_NUMBER()` at the top-25 boundary (12 teams flip eligibility). With the tiebreaker, ranks are deterministic and ROW_NUMBER-shaped; exact-tie labels may still differ ±n from the RPC's (its `ROW_NUMBER()` has no tiebreaker), which is acceptable — document this caveat in the migration comment. Verify `idx_rankings_full_age_gender` (and any state index) supports this; check with `EXPLAIN`.
     4. Filter both `state_rank <= p_rank_ceiling`, `ORDER BY (home_rank + away_rank) ASC LIMIT p_limit`.
   - **Single execution path (decided iteration 3 — do not build an in-route RPC call)**: the RPC is called **only by the pipeline with the service-role key** (no statement timeout), which then passes the computed matchups to the image route as a payload (step 3). Review-time `EXPLAIN ANALYZE` measured the correlated shape at 850 ms warm before final filters (each subquery bitmap-scans ~39K heap blocks; no covering index pairs `power_score_final` with the cohort columns) — too marginal for the 3s anon ceiling, and an anon-callable route query would have required tuning for no user benefit. Service-role-side, ~1s weekly is perfectly fine. Sanity-check correctness and runtime once via MCP `execute_sql` after applying the migration.
   - Returns per row: `game_date`, and for each side `team_id_master`, `team_name`, `club_name`, `state_rank`, plus shared `state_code`, `age_group`, `gender`.
   - Use the sargable ARRAY U18→U19 idiom from `20260609000000` if any age filtering is added. **Grant `EXECUTE TO authenticated` only — deliberately NOT `anon`**: this RPC is called exclusively by the pipeline with the service-role key (next bullet), and withholding the anon grant keeps a potentially heavy function off the public surface.
   - `games.game_date` is `DATE`; no kickoff-time column was verified during planning. Check the live schema at implementation (`information_schema.columns` for `games`); if no time column exists, captions/graphic show day labels (SAT/SUN + date) only — do not invent times.
   - Apply to prod via Supabase MCP `apply_migration` (no auto-deploy workflow exists; `CREATE OR REPLACE` is idempotent). Run MCP `get_advisors` after.

3. **Route: `/api/infographic/big-games`**
   - New `frontend/app/api/infographic/big-games/route.tsx`, `runtime = 'edge'`, composed from `_shared` (`Frame`, `Header`, theme, fonts, `INFOGRAPHIC_CACHE_CONTROL`).
   - Open with the sibling routes' guard: `if (!checkRateLimit(\`infographic:${getClientIp(request)}\`, 10, 60_000)) return new Response('Too many requests', { status: 429 })` (imports from `@/lib/api/rateLimit`), and attach `headers: { 'Cache-Control': INFOGRAPHIC_CACHE_CONTROL }` on the `ImageResponse` — exactly as `state`/`spotlight`/`movers` do.
   - **Pure renderer — no Supabase client, no RPC call.** The route takes its data from an `m` query param: base64url-encoded JSON `{v: 1, range: "Jun 13–14, 2026", games: [{cohort: "PA · U14 BOYS", day: "SAT", home: {name, club, rank}, away: {name, club, rank}, state: "PA"}, ...]}` (≤5 games; payload ~1KB, well under URL limits). **This supersedes the spec's big-games "Data"/"Graphic" bullets and Architecture section**, which still describe the pre-redesign anon-key route query, a `get_state_top10` RPC, and a kickoff time the data cannot provide — the spec file gets a matching amendment after this plan finalizes; until then the plan governs the big-games flow.

Decode as: translate base64url→base64 (`m.replace(/-/g, '+').replace(/_/g, '/')` + re-pad to a multiple of 4), then `JSON.parse(new TextDecoder().decode(Uint8Array.from(atob(b64), c => c.charCodeAt(0))))` — all inside a try/catch.
