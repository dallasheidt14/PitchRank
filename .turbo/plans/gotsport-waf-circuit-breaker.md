# Plan: GotSport CloudFront WAF Circuit-Breaker

## Context

GotSport added a CloudFront WAF in front of `system.gotsport.com/api/v1/*` (coincides with the reCAPTCHA-v3 rollout PR #713 noted on 2026-05-01). It is a **per-IP burst rate limiter**:

- Sustained ~15 req/s from one IP trips it (empirically measured 2026-05-18)
- A tripped IP returns HTTP 403 with `Server: CloudFront` and a CloudFront-branded HTML error body (`<TITLE>ERROR: The request could not be satisfied`) — distinct from a real "team not found" which is HTTP 404 with `Server: nginx` and JSON body `{"error":"Team Not Found"}`
- Lockout persists multiple minutes; fresh sessions and IP-level — cookies/headers don't help
- CI workflow `scrape-games.yml` survives because it runs 5 matrix shards on 5 separate runner IPs, each at `--concurrency 20`. From one residential IP, the CLI default `--concurrency 30` trips the WAF mid-run.

Current retry logic in `src/scrapers/gotsport.py:213-299` uses `retry_delay * 2**attempt` capping around 8 s — far shorter than the multi-minute WAF lockout — so 3 retries burn within ~10 s and the team errors out. There is no shared signal between workers, so all 30 concurrent threads independently retry-and-fail.

Goal: introduce a small circuit-breaker primitive that (a) detects WAF-class 403s specifically, (b) pauses all workers via a shared `asyncio.Event` while in OPEN state, (c) hard-fails the run cleanly if the WAF trips twice in the same session, and (d) lowers the local CLI concurrency default so a bare `python scripts/scrape_games.py` from a residential IP doesn't trip the WAF in the first place. CI behavior is unchanged.

### Convention Anchors

- **Retry layer split (`src/scrapers/_http.py:1-20`)**: urllib3 `Retry.status_forcelist` owns `[500,502,503,504]` only; **429 is owned at the app layer** (the `_http` helpers). `GotSportScraper` already deviates by having both. This plan does **not** correct that deviation (out of scope); it adds the WAF concern at the app layer only, keeping the existing urllib3 stack untouched.
- **Config via env vars with provider prefix**: `gotsport.py:86-90` uses `GOTSPORT_DELAY_MIN`, `GOTSPORT_MAX_RETRIES`, etc. New WAF knob `GOTSPORT_WAF_COOLDOWN_SEC` follows this prefix, read via `int(os.getenv("GOTSPORT_WAF_COOLDOWN_SEC", "300"))` in `__init__`.
- **Concurrency owned by orchestrator**: `scripts/scrape_games.py:422` creates the `Semaphore`; the scraper knows nothing about concurrency level. Workflow `scrape-games.yml:253-263` always passes `--concurrency` explicitly (20 sharded, 50 single-shard) — so lowering the CLI default in `scrape_games.py` has zero effect on CI.
- **Shared state across async workers**: One scraper instance per run, passed by reference into every `_scrape_team_concurrent` task. The new breaker is **module-level** in `gotsport.py` (IP-scoped, not instance-scoped); workers reach it via the scraper instance. No `asyncio.Event` / `asyncio.Lock` exists anywhere in `src/` or `scripts/` today — this is the first such primitive.
- **CI vs local detection**: project has **zero** Python-side CI detection today. CI vs local is distinguished only by the workflow passing different `--concurrency` values. We continue that convention: no `GITHUB_ACTIONS` env branching in Python; we just lower the CLI default. CI is unaffected because it always passes the flag explicitly.
- **Logging style for rate-limit / retry**: structured single-line WARNING with `%`-formatting and provider-prefixed greppable markers — e.g. `gotsport.py:228-233` `logger.warning("gotsport 429 retries: team=%s count=%d url=%s", ...)`. New breaker lines: `logger.warning("gotsport waf-tripped: cooldown=%ds attempt=%d teams_pending=%d url=%s", ...)` and `logger.info("gotsport waf-resumed: cooldown_elapsed=%ds")`.

### Proposed Alignment

The cleanest blend of existing conventions: (1) module-level `WAFBreaker` class + singleton in `gotsport.py` — matches the existing "one shared scraper, many workers" pattern and is IP-scoped not instance-scoped; (2) `WAFBlockedError(RateLimitedError)` reuses the documented "429 owned at app layer" exception type; (3) stdlib `asyncio.Event` + `threading.Lock` only — no new dependency, no library to learn; (4) CI concurrency stays workflow-driven (no Python CI detection); (5) follow `tests/unit/test_scrapers_http.py` for mocking and `tests/unit/test_scrape_games.py` for async test wiring. The breaker's detection function (`_is_cloudfront_waf_block`) is gotsport-specific (CloudFront-branded 403 body), keeping it in `gotsport.py` rather than `_http.py` until/unless a second scraper needs it.

## Implementation Steps

1. **Add `WAFBreaker` primitive + singleton + helpers in `src/scrapers/gotsport.py`**
   - Add module-level `_WAF_COOLDOWN_DEFAULT = 300` constant near the existing constants (top of file).
   - Add `class WAFBlockedError(RateLimitedError)` after the existing `TeamNotFoundError` (line 67). Import `RateLimitedError` from `src/scrapers/_http.py`. **`RateLimitedError.__init__` is keyword-only**: every construction site must pass all four args by keyword — `WAFBlockedError(provider="gotsport", url=api_url, last_retry_after=float(cooldown_sec), reason="cloudfront-waf")`. The same goes for `super().__init__(...)` inside `WAFBlockedError` if a subclass-level constructor is added.
   - Add module-level function `_is_cloudfront_waf_block(response: requests.Response) -> bool` that returns `True` iff `response.status_code == 403` AND `response.headers.get("Server") == "CloudFront"`. Do NOT depend on body parsing — header check is sufficient and faster.
   - **Detector scope note** (add as a `# NOTE` comment in the function body): the detector is keyed on **403 only**. CloudFront WAFs can also escalate to 503 for some throttle classes; today the urllib3 adapter at `gotsport.py:127-138` has `status_forcelist=[429,500,502,503,504]` which silently retries 503 three times and raises `RetryError` with `e.response is None` — invisible to this detector. If a future incident shows WAF 503s, both the urllib3 mount (drop 503 from forcelist, or move handling app-layer) and this detector must be widened in lockstep. Do NOT add 403 to the urllib3 `status_forcelist` without also updating the detector — that would mask trips.
   - Add module-level `class WAFBreaker` with: `_state: str` (`"closed" | "open"`), `_trip_count: int`, `_cooldown_sec: int`, `_lock: threading.Lock`, `_async_event: asyncio.Event` (initialized in `set()` state — workers proceed by default), `_open_until: float` (monotonic timestamp), `_resume_timer: Optional[threading.Timer]` (the one-shot resume scheduler — see `trip()` below), `_loop: Optional[asyncio.AbstractEventLoop]` (the orchestrator's event loop, captured at construction time so `_resume()` can `call_soon_threadsafe` to `set()` the async event from any thread).
     - **Event-loop binding (in `__init__`)**: try `self._loop = asyncio.get_running_loop()` inside `try/except RuntimeError`; if no loop is running yet (unit tests, sync-only callers including `scripts/process_missing_games.py:187` and `scripts/discover_u12_teams.py:55`), leave `self._loop = None` and add a public `bind_loop(loop: asyncio.AbstractEventLoop) -> None` method that the orchestrator calls once during startup (`scripts/scrape_games.py:run()`, just after `asyncio.run` enters — see Step 3) to thread the running loop into the singleton. **`bind_loop()` MUST call `self.reset()` before assigning `self._loop = loop`** so a long-lived process (test harness, future multi-`asyncio.run` orchestrator) doesn't start a new run with state inherited from the previous run (notably `_trip_count`, which would falsely abort on the first WAF hit). Without a bound loop, `_resume()` can still flip the `_state` flag (sync waiters work), but `_async_event.set()` cannot be safely invoked from a worker thread.
     - `trip(self, cooldown_sec: int, *, url: str = "") -> None`: under `_lock`, increments `_trip_count`. If `_trip_count == 1`: sets state to `"open"`, clears `_async_event` (workers will block — see clearing note below), sets `_open_until = time.monotonic() + cooldown_sec`, schedules a one-shot resume via `self._resume_timer = threading.Timer(cooldown_sec, self._resume); self._resume_timer.daemon = True; self._resume_timer.start()`. `threading.Timer` works identically from worker threads (where `trip()` actually runs, inside `asyncio.to_thread`) and from the main thread, with no event-loop dependency. Logs `logger.warning("gotsport waf-tripped: cooldown=%ds url=%s trip_count=%d", cooldown_sec, url, self._trip_count)`. If `_trip_count >= 2`: raises `WAFBlockedError(provider="gotsport", url=url, last_retry_after=float(cooldown_sec), reason="cloudfront-waf-second-trip")` — orchestrator catches and aborts. **`_trip_count` is monotonic across the run** — `_resume()` does NOT reset it. This is what enforces the "trips twice → abort" rule.
     - **`_async_event.clear()` note**: `asyncio.Event` is not thread-safe; calling `.clear()` from a worker thread is undefined behavior in some Python versions. To clear safely, `trip()` uses `self._loop.call_soon_threadsafe(self._async_event.clear)` when `self._loop` is set AND not closed (symmetric with `_resume()` below: `if self._loop is not None and not self._loop.is_closed(): self._loop.call_soon_threadsafe(self._async_event.clear)`); falls back to direct `self._async_event.clear()` when no loop bound OR the bound loop has been closed. The unbound-loop fallback path is reached by (a) pytest-asyncio test contexts that haven't called `bind_loop()`, and (b) **production sync callers** at `scripts/process_missing_games.py:187` and `scripts/discover_u12_teams.py:55` that construct `GotSportScraper` and call `scrape_team_games` directly without going through `scripts/scrape_games.py:run()`. Those sync callers have no async waiters, so the direct `.clear()` / `.set()` calls from the Timer thread are functionally harmless even when technically not thread-safe by spec.
     - `wait_if_open_sync(self) -> None`: thread-safe blocking wait used inside `scrape_team_games` (sync). Loop: under `_lock`, if `_state == "closed"` return; else read `_open_until`. Outside lock, `time.sleep(min(max(_open_until - time.monotonic(), 0.1), 1.0))`. After sleep, if `time.monotonic() >= _open_until`, call `_resume()` (idempotent). This sync polling is a belt-and-suspenders backstop — the primary resume trigger is the `threading.Timer` fired by `trip()`.
     - `async wait_if_open_async(self) -> None`: for use in orchestrator before entering semaphore. `await self._async_event.wait()`. Does NOT poll the clock — the `threading.Timer` scheduled by `trip()` is what eventually fires `_resume()`, which sets the async event via `_loop.call_soon_threadsafe(self._async_event.set)`. This is why `trip()` MUST schedule the timer; otherwise async waiters block forever if no sync caller ticks the clock.
     - `_resume(self) -> None`: under `_lock`, idempotent — if `_state == "closed"` return immediately. Else: set `_state = "closed"`. To set the `asyncio.Event` thread-safely, use `if self._loop is not None and not self._loop.is_closed(): self._loop.call_soon_threadsafe(self._async_event.set)` else direct `self._async_event.set()`. Log `logger.info("gotsport waf-resumed: cooldown_elapsed=%ds trip_count=%d", elapsed, self._trip_count)`. Called from three sources: (a) the `threading.Timer` callback armed by `trip()` (primary), (b) the `wait_if_open_sync` belt-and-suspenders poll, (c) `reset()` in tests. All idempotent thanks to the early-return.
     - `trip_count` property (read-only, no lock — `int` read is atomic in CPython for telemetry).
   - **Trip-attempt lifecycle (state explicitly so future maintainers don't "fix" it)**: a single team's worst-case wall time when WAF-tripped is **one cooldown** (~5 min default), not `max_retries × cooldown`. Sequence: attempt 0 hits WAF → `trip()` (count=1) → `continue` → attempt 1 waits 5 min via `wait_if_open_sync` → attempt 1 either succeeds (done) OR hits WAF again → `trip()` raises `WAFBlockedError` (count=2) → run aborts. Attempt 2 is never reached in the WAF-trip path.
   - Add module-level singleton: `_waf_breaker = WAFBreaker()`. Expose via module-level `get_waf_breaker() -> WAFBreaker` accessor (testability: allows test to reset singleton state via attribute access).
   - Add `reset()` method on `WAFBreaker` (under `_lock`: cancel `_resume_timer` via `self._resume_timer.cancel()` if not None and set to None; **clear `self._loop = None`** so a closed/dangling loop reference doesn't leak into the next bind/test/run cycle; set `_state = "closed"`; set `_trip_count = 0`; set `_async_event` directly — tests run without an event loop bound or with their own loop, so `call_soon_threadsafe` is unnecessary here). Tests call this in `tests/conftest.py` (see step 5), and `bind_loop()` calls it before binding the new loop (see same Step 1, below) so each `asyncio.run` entry starts from a clean state.
